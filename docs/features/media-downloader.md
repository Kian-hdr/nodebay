# Media downloader

Nodebay accepts explicit HTTP or HTTPS media URLs through drop, the shelf's Add Link popover, Downloader Settings, Command-V while the pointer is inside an open notch, or the download control shown for a connected YouTube browser-tab media source. All entry points create the same persistent job. yt-dlp inspects and downloads directly from the Mac to Nodebay-managed local storage by default, which avoids repeated Downloads-folder permission prompts. Users can select a custom download folder once in Settings; Nodebay retains its security-scoped bookmark.

Automatic is the recommended default and does not show a format popup. YouTube Music and extractor-confirmed audio-only or structured track **and artist** metadata select MP3. Ambiguous standard YouTube content, including Shorts, selects MP4 so video is not discarded. Titles, music categories alone, and the presence of an audio stream never establish that an upload should lose its video. The classifier checks available video formats as well as the selected stream.

The tile shows its effective Audio/MP3 or Video/MP4 choice and offers a one-click Audio or Video override. More options include Best Original and returning to the saved mode. Overriding waits for the previous job to stop; it does not change Settings. Settings provide Automatic, Always Video, Always Audio, and Ask Every Time, saved resolution and bitrate, and the starting format for Ask Every Time. Automatic deliberately chooses MP3 or MP4 rather than that starting format. Best audio quality requests FFmpeg quality 0; explicit bitrates are passed in kbps.

MP3 never starts when FFmpeg is unavailable. Audio choices are disabled and FFmpeg installation help is available. Video and Original remain usable for a single combined stream without FFmpeg, but separate-stream merging is disabled and available resolutions may be lower. Metadata embedding also requires FFmpeg. FFmpeg and yt-dlp remain unmodified, separately installed companions.

Playlists always require confirmation. In Automatic mode, Nodebay fully inspects and classifies each item rather than guessing one format for the whole playlist. Fixed Audio or Video settings and one-time overrides apply one format to every item. Partial successes are preserved, and completed playlist items become a File Stack.

Classification diagnostics retain only fixed reasons, confidence, the audio/video choice, and playlist item ordinals. They never include track titles, artists, URLs, or video identifiers. The existing local download history separately retains job titles and URLs for Retry. Empty or uninspectable playlists fail recoverably instead of applying the parent classification to unseen items. Single successful playlist results still become a stack. Cancelling a playlist retains already completed files in a result stack and never deletes user files.

Metadata fields and selection syntax follow the [official yt-dlp documentation](https://github.com/yt-dlp/yt-dlp#output-template). Site metadata can change; ambiguous or incomplete evidence falls back to video.

The unreleased revision's [verification report](../automatic-download-verification.md) separates executed tests and clean builds from pending physical UI and live-service checks.

URLs are passed as structured arguments, credentials in URLs are rejected, output templates are restricted, path traversal is rejected, browser cookies and plugins are disabled, and no shell is used. Downloads use a job-owned staging directory and collision-safe promotion. Cancellation cleans only staging data; completed and partially successful files remain in the selected directory and are added to the shelf. YouTube has the primary tested experience. Other yt-dlp sites are explicitly shown as experimental because upstream site support changes. Copyright and service permissions remain the user's responsibility.
